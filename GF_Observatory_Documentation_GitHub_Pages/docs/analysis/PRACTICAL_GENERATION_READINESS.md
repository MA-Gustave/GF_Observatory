# GF Observatory — Practical generation suitability (prototype)

**Implementation scope:** `GF_Observatory/tools/practical_catalog.py` is a
runnable read-only **prototype**. The principal Observatory product remains
unimplemented in the supplied repository snapshot. This feature is a separate
application dimension and **does not redefine** normative `R0`–`R7` maturity
and readiness, the 14 existing signals, or the canonical analysis-profile score.

Inputs:

1. A source inventory (`gf-practical.rgl-inventory` v1.0), generated by Ars
   Magna Lulli's RGL scanner. Names and paths are structural hints, not success.
2. A pinned practical profile (`gf-practical.profile` v1.0) from WordBench.
3. Per-language `practical_coverage.json` sidecars from WordBench, **alongside**
   original `summary.json` and `manifest.json` in a versioned run directory.

The Observatory adapter rechecks the canonical manifest and **every declared
artifact SHA-256**, source run identity, the profile digest and scenario-level
passing claims. A missing/invalid manifest means `unverified`, never `ready`.
The sidecar is not inserted in, and never modifies, WordBench's manifest.

Run (from the root of the Observatory repository):

```shell
python tools/practical_catalog.py \
  --inventory /path/to/rgl_inventory.json \
  --practical-profile /path/to/GF_Wordbench/profiles/practical_generation_v1.json \
  --reports-root /path/to/wordbench_results \
  --output /path/to/practical_catalog.json \
  --csv /path/to/practical_catalog.csv
```

If the RGL suffix (`Eng`) differs from the WordBench project ID (`english`),
provide a JSON identity map via `--identity-map /path/to/map.json`, such as
`{"Eng": "english"}`. Identity never defaults to a heuristic match.

Catalog statuses: `ready`, `needs_work`, `unverified`. Missing evidence is
not evidence of missing linguistic coverage. The catalog separately emits
`structural_gaps`, which indicate absent conventional module names but are
**not** automatically practical semantic gaps. Only `failed` test scenarios
create practical `missing` entries.

The prototype provides a standalone desktop diagnostic GUI (`GF_Observatory_Diagnostic.pyw`) but has no built-in repository sync, GF compiler, web dashboard,
SQLite storage or scheduled background verification.
